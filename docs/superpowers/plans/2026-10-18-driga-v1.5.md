# Driga v1.5 (fleet pull, Linux, MCP, OTLP intake) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** From any paired machine, see and act on every machine's agents (viewer pulls from `driga serve` peers over mTLS + SSE), with Linux collection so cloud VMs can serve, plus `driga mcp` and an optional loopback OTLP intake.

**Architecture:** Every machine runs the same collector. A serving collector appends a `feed` row for every change in the same transaction as each pass and exposes `/v1/hello|snapshot|events|ack|pair/*` over pinned-certificate mutual TLS; a viewing collector runs one puller per peer that snapshots, follows SSE from a cursor, and applies remote rows under the peer's `machine_id` (single writer per DB preserved). Readers (CLI, TUI, MCP) read merged rows.

**Tech Stack:** Go 1.27, existing v1 deps; standard library `crypto/tls`, `crypto/x509`, `crypto/ecdsa`, `crypto/hkdf`, `net/http`; `github.com/modelcontextprotocol/go-sdk` v1.8.0 (only new module). gopsutil v4 Linux backend, kardianos/service `UserService`.

**Spec:** `docs/superpowers/specs/2026-10-18-driga-v1.5-design.md` (binding; § references below point into it). v1 spec `docs/specs/2026-10-18-driga-cli-tui-design.md` still applies.

## Global Constraints

- All v1 Global Constraints (`docs/superpowers/plans/2026-10-18-driga-v1.md`) hold, except "no network calls anywhere" becomes: the collector makes no network calls unless fleet is configured (§3).
- A listening port opens only when `[fleet] serve = true` and `listen` names an explicit address; refuse `0.0.0.0`/`::` and non-private addresses unless `allow_any_address = true` (§7.7, §18.1). OTLP intake binds loopback only.
- TLS 1.3 minimum, `tls.RequireAnyClientCert`, pinned SHA-256 DER fingerprints via `VerifyPeerCertificate` (+`InsecureSkipVerify`), constant-time compare; no CA, no shared secret (§4.2.5).
- Trust files `fleet/{identity.key,identity.crt,peers.json,viewers.json,enroll.json}` and `fleet.sock`: files `0600`, dir `0700`, atomic temp+rename writes; serve refuses if key is group/world readable (§7.6).
- `share_text` default `"titles"`; snippets only with peer `share_text = "snippets"` and local `capture_text = "snippets"`; procs agent-classified only, cmdline scrubbed + truncated 200 chars; git remote URL credentials stripped (§12, §18.4).
- Views merge all machines by default; `--machine <name|id|local|all>` (default `all`) (§18.2).
- Feed: `seq INTEGER PRIMARY KEY AUTOINCREMENT`, `feed_epoch` random 128-bit hex in meta, retention 30 d or 200 000 rows, `resnapshot` on epoch mismatch / pruned cursor / slow viewer (buffer 1 000) (§6.3, §13).
- SSE: `id: <epoch>:<seq>`, `event: <kind>`, JSON `data`, `retry: 2000`, `: ping` every 15 s, 204 = stop; viewer backoff 2 s → 60 s jittered; peer `live` iff event/ping < 45 s (§4.2.8, §8).
- Pairing: enrollment window default 10 min, ≤ 3 attempts, closes on success; code = HKDF-SHA256(ikm=nV‖nP, salt="driga-pair-v1", info=fp(certV)‖fp(certP)‖ekm) → 6 digits by rejection sampling; ekm = `ExportKeyingMaterial("EXPORTER-driga-pairing", nil, 32)`; confirm timeout 2 min (§7.2).
- Default ports: fleet `7411`, intake `127.0.0.1:7418` (§4.2.18). Accept rate ≤ 10/s, ≤ 16 concurrent conns, handshake timeout 5 s (§7.7). Bodies ≤ 8 MiB; viewer snapshot cap 64 MiB.
- Linux: data dir `$XDG_DATA_HOME/driga` (default `~/.local/share/driga`), logs journal or `$XDG_STATE_HOME/driga/collector.log`; `pressure_free = MemAvailable/MemTotal×100`; nullable `psi_mem_some10`; orphan reparent = PPID 1 or user's `systemd --user` pid (§5.8).
- OTLP intake: JSON only (protobuf ⇒ 415), gzip accepted, never creates sessions, drops content attributes at the door (§5.6, §18.6).
- MCP: stdio, read-only, tools exactly as §10, envelopes byte-identical to `--json`.
- Binary growth ≤ 8 MiB stripped; collector RSS < 50 MB with serve + 2 viewers (§2 goal 8, §3).
- Tests: never real HOME/agent dirs/network beyond 127.0.0.1; fleet tests run two collectors in-process or as subprocesses with temp `DRIGA_*` dirs and `listen = "127.0.0.1:0"` (chosen port written to `fleet/listen`).
- Commits: one commit for the whole run (`feat: driga v1.5 fleet, Linux, MCP, OTLP intake`); per-task "Commit" steps are checkpoints.

## Review Focus

1. **Remote orphans must never be killed locally**: `driga orphans kill <id>` / TUI `k` on an orphan whose `machine_id` is remote refuses with `orphan is on <name>; run driga orphans kill there` — pinned in Task 9 (`TestKillRefusesRemoteOrphan`).
2. **Same paths on two machines** (`~/code/api` on laptop and VM): repos/worktrees/sessions stay distinct per `machine_id`; `--project .` resolves against local repos only; conflicts never pair sessions from different machines — pinned in Task 3 (`TestSamePathTwoMachines`) and Task 9 (`TestConflictsNeverCrossMachines`).
3. **Peer clock ahead of the viewer** (skew +5 min): ages never negative, labels computed with the peer's own observed_at, `driga machines` warns — pinned in Task 8 (`TestApplyClampsFutureTimestamps`).
4. **Rows pruned between snapshot and resume / peer DB recreated**: viewer never silently skips — epoch or retention mismatch yields `resnapshot` and a fresh snapshot — pinned in Task 6 (`TestResumeAfterPruneResnapshots`) and Task 8 (`TestEpochChangeResnapshots`).
5. **Remote rows not growing without bound**: per-peer procs/samples replaced/pruned like local ones; removing a peer with `--purge` deletes its rows; viewer applies its own retention to silent peers — pinned in Task 8 (`TestRemoteRetention`).
