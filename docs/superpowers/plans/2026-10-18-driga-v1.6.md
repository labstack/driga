# Driga v1.6 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the Gemini CLI adapter, agy process-level sessions plus a schema tool, disk cleanup, opt-in `claude -p` project summaries, and `driga ask`.

**Architecture:**
- **Adapters:** both new ones plug into the existing `adapter.Adapter` and signature TOML.
- **Cleanup:** a new `internal/cleanup` package, run by the CLI with live, read-only git and process inspection plus re-verification at action time, like `internal/kill`.
- **LLM runner:** summaries and `ask` share `internal/llm`, which probes `claude --help`, fails closed, and isolates the child.
- **Summaries:** results reach the DB through the spool, so the collector stays the only writer.

**Tech Stack:** Go 1.27, cgo-free; kong; Bubble Tea v2; modernc sqlite + goose; go-sdk MCP v1.8.0.

**Spec:** `docs/superpowers/specs/2026-10-18-driga-v1.6-design.md` (builds on v1 and v1.5 designs).

## Global Constraints

- Module `github.com/labstack/driga`; `CGO_ENABLED=0`; `GOOS=linux go build ./...` passes; macOS-only code in `*_darwin.go`.
- Single writer: only the collector writes `driga.db`. CLI commands write the spool, trust files, `cleanup.log`, or nothing.
- JSON envelope `{"schema":2,"observed_at","mode","freshness","coverage_gaps","data"}` for every new `--json` output and MCP tool.
- Tests never touch real `~/.claude`, `~/.codex`, `~/.gemini`, Driga data dirs, or `claude` itself. Use temp HOMEs, the `DRIGA_*` env vars, and a fake `claude` script on `PATH`.
- No destructive action without `y` (or `--yes`); `--dry-run` prints exact commands; everything is re-verified at action time; local machine only.
- Never delete agent history; never `git branch -D`; never remove the main or a locked worktree; never remove ignored non-regenerable files without `--include-ignored` for that candidate.
- `claude -p` only through `internal/llm`. Every child gets `DRIGA_INTERNAL=1` and `--name driga-internal`, and has its required flags verified via `claude --help` first. Summaries are off unless `[summaries] enabled = true`. No background LLM calls.
- Summary inputs never include transcript lines or file contents. Handoff text is used only when `capture_text = "snippets"`, and a summary built from it is shared only at `share_text = "snippets"`.
- No curve-fitting: Gemini fixtures are synthetic files built from the format verified in the spec §4.1. The agy adapter reads no transcript tables in v1.6.
- Footprint: `scripts/footprint.sh` still PASSes (collector < 50 MB). Cleanup size walks and LLM calls never run in collector passes.
- One commit at the end of the run.

## Review Focus

1. **A worktree whose state changes between list and action:** new commit, new untracked file, an agent `cd`s in. Expected: the action refuses with the reason, and nothing is removed.
2. **A Gemini `.jsonl` file rewritten by recovery** (rename; the new file is shorter than the stored offset), and a `$rewindTo` that removes the last user message. Expected: offsets reset, and the fold matches a fresh read.
3. **`claude` missing, too old (a required flag absent), exiting non-zero, or printing non-JSON.** Expected: a clear error, no spool write, and no partial summary.
4. **Summary at a `titles` peer with snippet capture on.** Expected: the feed never carries the `used_snippets` summary.
5. **Symlink or path tricks in a scratch candidate** (a symlink pointing outside the temp root, `..` in a session id). Expected: refused; nothing outside the root is moved.

### Task 7: Cleanup core

- Create in `internal/cleanup/`: `cleanup.go`, `worktree.go`, `scratch.go`, `history.go`, `trash_darwin.go`, `trash_linux.go`, `trash_other.go`, `size.go`, `cleanup_test.go`

**Interfaces:**
- Produces:
  - `type Kind string` with values `worktree`, `scratch`, `history`.
  - `type Candidate struct{ ID string; Kind Kind; Path string; Repo string; Branch string; Evidence []string; Status string /* ready|needs_review|report_only */; Size int64; SizeCapped bool; Ignored []IgnoredPath }`
  - `type IgnoredPath struct{ Path string; Regenerable bool; Size int64 }`
  - `cleanup.List(ctx, env Env) ([]Candidate, error)`
  - `cleanup.Verify(ctx, env Env, c Candidate) error`, which re-checks every condition.
  - `cleanup.Apply(ctx, env Env, c Candidate, opts ApplyOpts) (Result, error)`, which calls Verify first and appends one JSON line to `<data dir>/cleanup.log`.
  - `type Env struct{ Store *store.Store; Plat platform.Platform; Home, DataDir string; Now time.Time; Cfg config.CleanupConfig; Git func(ctx, dir string, args ...string) ([]byte, error) }`
  - `ApplyOpts{DryRun, IncludeIgnored bool}`
  - IDs are stable: `wt:<sha256(path)[:12]>`, `scratch:<session id>`.
  - Config `[cleanup] worktree_idle = "168h"`, `low_disk_percent = 10`, `low_disk_bytes = "10GiB"`, `regenerable = [...]` with the spec §4.4 default list.
- Worktree rules and commands are exactly as in spec §4.4.
- Scratch roots are Claude Code's per-session temp dirs `<tmp>/claude-<uid>/<project slug>/<session id>/`, where `<tmp>` is `/tmp` (and `/private/tmp` on macOS) and `$TMPDIR`. The session id must match a stored session row, and that session must be `dead` or `finished` for ≥ 24 h. History candidates are report_only sizes per store.
