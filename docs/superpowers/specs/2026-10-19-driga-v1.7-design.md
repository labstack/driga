# Driga v1.7 design: TUI home dashboard and `driga web`

Status: approved by the maintainer ("Go for it", 2026-10-19). Ideas page with
mockups: https://claude.ai/artifact/4ShET11pS9Q7WJ3Dhu5f9c

## 1. Intent

`driga top` today is six tables behind tabs. v1.7 makes Driga something you can
leave open: a TUI home screen that answers "does anything need me?" at a
glance, and a separate browser dashboard for the same data. The maintainer
asked for the two to be **separate products**: each is designed for its own
medium, and both read the same view layer. The TUI is not streamed to a
browser, and the web page is not a terminal emulator.

## 2. Goals

- TUI: a Home tab with attention items, state counts, machine gauges,
  activity sparklines, project cards and leftovers, readable at 80 columns
  and rich at 160+.
- TUI: a split list/detail layout on wide terminals.
- Web: `driga web` serves a read-only dashboard on loopback with live updates.
- Both use only data Driga already stores. No new collection.

## 3. Non-goals and anti-goals

- No actions from the browser in v1.7 (kill, ack, cleanup stay in CLI/TUI).
- No remote access: the web server never listens on a non-loopback address.
- No Node toolchain, bundler or CDN at runtime. `go install` must keep working.
- No new work inside the collector process; its 50 MB RSS budget is untouched.
- No invented numbers: every chart shows stored samples or events.

## 4. Shared data: `view.Activity`

A new view returns the last 60 minutes in one-minute buckets for the selected
machine scope: machine sample values (load1, memory used and total, swap used
and total, memory pressure) taken from `machine_samples`, and the count of
`events` per minute across sessions. Minutes without a sample carry no value
(a gap, never a zero). It follows the existing view conventions (Reader,
Filter, schema-1 envelope) and is exposed as `driga activity --json` and as
the MCP tool `driga_activity` so both front ends and agents agree.

## 5. TUI

Stack: Bubble Tea v2, Bubbles v2, Lip Gloss v2 (in use), plus
`github.com/NimbleMarkets/ntcharts/v2` v2.5.0 for sparklines and bars.

- **Home tab (key `0`)**, the tab `driga top` opens on. Existing tabs keep
  keys `1`–`6`.
  - "Needs you": waiting, stalled? and unacknowledged finished sessions,
    newest first, Enter opens the agent, `x` acknowledges (same rules as the
    Inbox tab).
  - Agent state counts as colored bars.
  - Machine: memory and swap bars, load sparkline, disk free.
  - Activity: events/minute and load sparklines over 60 minutes.
  - Projects: one line each with a dot per agent colored by state, branch,
    dirty, unpushed, latest handoff or title.
  - Leftovers: orphan count and reclaimable MB, ready/refused worktree counts,
    agent history size if already measured (no new walks).
  - Layout reflows: three columns at >= 150 columns, two at >= 110, one below.
- **Split detail**: at >= 140 columns the Agents tab shows the list on the
  left and the selected agent's detail on the right, updating as the cursor
  moves. Narrower terminals keep Enter/Esc.
- State colors are fixed in meaning everywhere (working green, waiting amber,
  stalled? red, idle blue, finished dim) and respect `NO_COLOR`.
- Motion is limited to ntcharts redraws; no blinking. (Builder's call:
  harmonica and bubblezone are left out of v1.7 to keep the dependency set
  small; Bubble Tea v2's own mouse events may be used for tab clicks.)

## 6. Web (`driga web`)

Stack: Go `net/http` and `html/template`, htmx 2.0.4 with the SSE extension
2.2.2, uPlot 1.6.31, hand-written CSS. All files are embedded with `go:embed`
from `internal/web/static/`; the vendored libraries in `static/vendor/` are
verified copies with their licenses (`LICENSES.txt`).

- **Command**: `driga web [--listen 127.0.0.1:0] [--open]`. Prints the URL.
  `--listen` accepts only loopback addresses (127.0.0.1, ::1, localhost);
  anything else is an error. `--open` opens the browser.
- **Process**: its own process, never inside the collector. It reads the
  database read-only using the same daemon/snapshot decision as the TUI
  (when no collector is running it shows the same "collecting a snapshot"
  notice and keeps a disposable snapshot fresh, like `driga top`).
- **Auth**: a random 32-byte token in the printed URL. The first request
  with `?token=` sets an HttpOnly, SameSite=Strict cookie and redirects to the
  clean URL. Every request needs the cookie. Requests whose Host header is not
  the listen address (or `localhost:<port>`) are rejected (DNS rebinding).
- **Methods**: only GET and HEAD. Anything else is 405.
- **Headers**: `Content-Security-Policy: default-src 'self'; script-src 'self';
  style-src 'self'; img-src 'self' data:; connect-src 'self'; frame-ancestors
  'none'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`,
  `Cache-Control: no-store` for pages and data. No inline scripts or styles.
- **Pages**: Home (same sections as the TUI Home), Agents, Agent detail,
  Projects, Project detail (`where`), Inbox, Orphans, Machines, Cleanup (list
  only, with `--why` reasons). Machine scope selector when fleet machines
  exist (builder's call: fleet is shown, read-only, because the views already
  merge it).
- **Live updates**: one SSE endpoint. The server checks the database data
  version about once a second and sends an event when it changes; htmx
  re-fetches the visible fragments. No polling from the browser otherwise.
- **Design**: its own visual language for the browser (not a terminal look):
  light and dark themes from tokens, the same state colors as the TUI,
  responsive down to phone width, tabular numbers, state shown as chips and
  severity stripes as well as text.
- **Escaping**: all stored text (titles, prompts, paths, command lines) goes
  through `html/template` escaping. No `template.HTML` on stored data.

## 7. Testing

- `view.Activity`: buckets, gaps for missing samples, event counts, machine
  scope.
- TUI: renders Home at 80, 120 and 160 columns with no line wider than the
  terminal; needs-you ordering; split detail appears only at >= 140.
- Web (`httptest`): no cookie or token is 401; token sets cookie and
  redirects; wrong Host is rejected; POST is 405; non-loopback `--listen`
  errors; security headers present; every page renders against a fixture
  store; a session title containing `<script>` is escaped; the SSE endpoint
  emits after a data change.
- Smoke test: start `driga web` against the smoke fixture, fetch Home and
  Agents with the token, check the fixture session title appears.

## 8. Decisions recorded as the builder's calls

1. Home is a new tab `0` and the default view; `1`–`6` unchanged.
2. Web is read-only in v1.7.
3. Web shows fleet machines with a scope selector.
4. harmonica and bubblezone are not added in v1.7.
