Driga raises a desktop alert when a session needs you. The alert shows the
session title or project and why it needs you, within your capture policy.

Alerts come from the Driga app, which runs the collector and posts what it
raises. Keep Driga running: closing its window leaves it collecting in the
menu bar or tray, and it starts at login.

```sh
driga app
```

Clicking an alert brings Driga forward on the session it is about, without
acknowledging it, also when the window was closed. Summaries and machine
warnings open the window. Clicks work the same on macOS, Linux and Windows.

## macOS

Notifications need the installed **Driga.app**, which the Homebrew cask
provides:

```sh
brew install --cask labstack/tap/driga
```

They use Driga's name and icon through the native notification API; no helper
is needed. Builds run from a checkout or `go run` cannot send macOS
notifications, and `driga doctor` explains how to install the app.

macOS asks once whether Driga may send notifications. If the prompt was
declined, turn on **Allow notifications** in **System Settings → Notifications
→ Driga**.
`driga doctor` warns when notifications are off and prints the command that
opens that page. Turning them back on takes effect from the next
alert; alerts raised while they were off are not replayed, and stay in the
inbox.

## Linux and Windows

The app's alerts use the desktop's notification service on Linux and native
toasts on Windows, where Focus Assist or notification policy can suppress
them. `driga doctor` reports availability.

## Headless machines

Without the app, the collector service posts alerts itself:

```sh
driga service install
```

On macOS it uses the installed Driga.app's identity, and clicking a local
item's notification runs `driga inbox jump <item-id>` without acknowledging
it. A jump selects a proven tmux pane, focuses a proven Terminal or iTerm
window when `inbox.jump_terminal = true`, or prints a resume command. Machine
warnings open Terminal on the Machines tab. Batch summaries and remote alerts
have no click action. Linux uses `notify-send`, and Windows uses plain toasts
with a per-user `LabStack.Driga` identity; neither has click actions.

## Health warnings

Machine health warnings, such as low disk, notify once per condition until it
clears. Concurrent warnings from one machine form one summary. Details and
cleanup commands stay in the inbox.

## Tune alerts

```toml
[inbox]
alerts = "waiting"      # "all" adds completions, "off" disables alerts
alert_after = "0s"      # only alert when a wait is still open this long
alert_repeat = "5m"     # minimum interval between alerts for one session
jump_terminal = false   # bring a proven macOS terminal window to front
```

`alert_repeat` throttles session alerts, not health warnings. Every key is in
the [settings reference](/reference/settings#inbox-and-alerts).
