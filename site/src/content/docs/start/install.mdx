<TabItem label="macOS">

Install the signed and notarized release with Homebrew:

```sh
brew install --cask labstack/tap/driga
```

The cask installs `Driga.app` in `/Applications` and links `driga` to the CLI
inside it. Open Driga from Finder or Spotlight, or run `driga app`. Its first
launch installs the Driga service, `drigad`, which collects from login, sends
[desktop notifications](/guides/notifications) and runs Chat whether or not the
app is open. After `brew upgrade`, a running app relaunches itself on the new
version and restarts the service on it. The first launch also removes the
collector an earlier release installed.

The app reads `DRIGA_*` variables from its own environment, not your shell
profile: `driga app` passes the terminal's on to it, and the service it
installs keeps them. It logs to the Driga service log, which `driga service logs`
prints.

</TabItem>
<TabItem label="Linux">

Debian `.deb` and RPM `.rpm` packages, plus `tar.gz` archives for amd64 and
arm64, are on [GitHub Releases](https://github.com/labstack/driga/releases).
Verify each download against `driga_<version>_checksums.txt` before
installing.

The packages install `driga.desktop`, so Driga appears in your launcher, and
recommend GTK 3, WebKitGTK and an AppIndicator library for the app. The tray
needs a desktop with a StatusNotifierItem host; GNOME needs an extension. The
desktop app on Linux is best effort.

On a VM or server, run the Driga service as a systemd user service instead, and
allow it to run after logout:

```sh
driga service install
loginctl enable-linger "$USER"
```

Without systemd, run `driga service run` under tmux or nohup instead.

</TabItem>
<TabItem label="Windows">

Windows support is [experimental](/guides/windows). Install with Scoop:

```powershell
scoop bucket add labstack https://github.com/labstack/scoop-bucket
scoop install labstack/driga
```

Scoop installs the app, `Driga.exe`, with a Start menu shortcut, and puts the
CLI, `bin\driga.exe`, on `PATH` as `driga`. Archives with both are also on
[GitHub Releases](https://github.com/labstack/driga/releases). Keep them at a
stable path without shell metacharacters before installing hooks or the
service. The app's first launch removes the Driga service task installed earlier and
says so once.

</TabItem>
<TabItem label="From source">

Use the Go version in `go.mod` or newer. This builds the CLI; the packaged
app, with its name, icon and notifications, comes from a release:

```sh
CGO_ENABLED=0 go build ./cmd/driga
./driga version
```

`go install ...@<tag>` does not work: CalVer tags use the year as their major
version, which Go module rules reject for this module path. Use a package, an
archive or a checkout.

</TabItem>
</Tabs>

## Before hooks or the service

Keep Git on `PATH` and the installed binary at a stable absolute path. Hooks
and the Driga service record that path; moving the binary afterwards breaks
them until you reinstall them.

Check the install:

```sh
driga version
driga doctor
```
