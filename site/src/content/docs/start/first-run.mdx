## Look first, configure nothing

```sh
driga            # the terminal UI: Flow, Projects and Machines
driga summary    # one-screen text summary
```

Without the Driga service, Driga takes a disposable snapshot and says
`snapshot · no history`. Nothing is written to a database. One agent in one
repository works without configuring roots or a service: session working
directories are enough to discover repositories.

## Set it up properly

<Steps>

1. **Run guided setup** (optional). Each step previews its change and asks:

   ```sh
   driga init
   ```

   It covers repository roots, text capture and hooks, and how to collect: on
   macOS and Windows it points to the app, on Linux it offers the service. You
   can do each one by hand instead, as below.

2. **Start collecting** for history, the inbox and alerts. On a desktop, open
   Driga from Finder, the Start menu or your launcher, or from a terminal:

   ```sh
   driga app
   driga doctor
   ```

   The app installs the per-user Driga service and makes sure it is running.
   The service collects and posts alerts independently of the app. Closing the
   window or choosing Quit leaves the service running. Installation removes
   only legacy collector jobs from earlier releases.

   On a headless machine, install the same service from the CLI:

   ```sh
   driga service install
   driga doctor
   ```

   The service is a per-user LaunchAgent on macOS, a systemd user service on
   Linux and a Task Scheduler task on Windows. The first import marks older
   events as already seen.

3. **Install agent hooks** for attention events, Claude permission prompts and
   Copilot sessions. Preview the diff first:

   ```sh
   driga hooks install --dry-run
   driga hooks install
   driga hooks status
   ```

   Pass an adapter to limit the change: `claude`, `codex`, `copilot` or `all`
   (the default). Restart running agent sessions afterwards. The exact events
   are in the [hooks reference](/reference/hooks).

4. **Open a view.**

   ```sh
   driga top              # terminal UI
   driga app              # desktop app
   driga inbox --since yesterday
   ```

</Steps>

Reading an inbox item never acknowledges it. Acknowledge with
`driga inbox ack <item-id>` or from the Activity section in Flow.

## Service commands

On a headless machine, manage the Driga service with:

```sh
driga service status
driga service logs -f
driga service stop
driga service start
driga service restart
driga service uninstall
```

On macOS the label is `run.driga.service` and logs are at
`~/Library/Logs/driga/service.log`. On Linux, `driga service logs -f` wraps
`journalctl --user -u driga`.

## Undo

`driga hooks uninstall` removes only Driga's entries, and
`driga service uninstall` removes the service. Turn off launch at login in
Driga's Settings window. Your agent configuration is changed only by these
explicit commands.
